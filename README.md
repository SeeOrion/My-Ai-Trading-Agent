# AI Trading Agent

一个以研究和模拟交易为优先、遵循领域驱动设计（DDD）的量化交易智能体。

接手开发或导入新的 AI 对话时，请先阅读 [AI_README.md](AI_README.md)。其中包含完整的项目地图、DDD 分层、数据源与降级逻辑、关键文件索引、安全边界和验证方式。

## 当前状态

AI 模拟选股与交易支持“新建账户 / 切换账户”：同一市场可建立多个独立模拟账户。新建时设置市场和本金，创建后通过账户设置选择策略与持仓上限。账户各自保存持仓和历史，个人纪律按账户独立勾选；切换页面不会暂停其他启用账户的定时复核。

收盘价现可持久化到 PostgreSQL，取数失败时复用相同已结束交易日的缓存并显示日期与来源。月盈亏以本月新仓的买入均价、或跨月持仓的月初前收盘价为基准；缺少月初基准时按买入成本估算并提示。页面“本月持仓盈亏”仅覆盖当前持仓，不含已平仓收益、分红和手续费。

模拟持仓支持“刷新收盘价”：按最近已结束且有数据的交易日重新计算估值与盈亏，显示价格日期，不执行买卖。AI 账户可切回“刷新最新行情”。定时复核在运行暂停后遇到网络错误会提示疑似休眠，并保留诊断详情；此提示不代表数据授权已经失效。

已实现供应商无关的行情、财经快讯采集与新闻情绪分析，以及基本面、资金流、期权到期损益分析。因子库现提供严格的声明式注册表和 HTTP 查询 API。策略注入、文档/OCR、交易日志的私有 PostgreSQL 数据模型与前端入口已就绪，业务用例将在下一阶段接入。

系统默认**不连接券商、不下单**。任何未来实盘能力都必须是显式配置、独立授权并经过风险约束的可选模块。

## 使用 uv

后端由 `backend/` 内的 `uv` 项目管理依赖和 `.venv`。首次进入项目或依赖变更后执行：

```bash
cd backend
uv sync --all-extras
```

不需要手动 `source .venv/bin/activate`。所有 `uv run` 命令都会自动发现并在
`backend/.venv` 中运行；例如：

```bash
cd backend
uv run pytest
uv run ruff check .
```

## 前后端与私有部署

`backend/src/ai_trading_agent` 是 Python 后端（DDD 核心与 FastAPI 交付层），`frontend/` 是独立的
React/Vite 工作区。前端只访问 `/api/v1`，不会保存或读取任何数据源、LLM、数据库密钥。

本地开发可分别启动：

```bash
# 终端一：后端
cd backend
uv run uvicorn ai_trading_agent.interfaces.api.app:app --app-dir src --reload --port 8000

# 终端二：前端
cd frontend
npm run dev
```

`docker-compose.yml` 提供凭据初始化、PostgreSQL、一次性数据库迁移、后端和静态前端五个独立服务。
后端从仓库根目录私有 `.env` 读取 Tushare、LLM 和定时任务设置；Compose 会用容器内连接串覆盖
`DATABASE_URL`。首次启动时，`credential-init` 会自动生成数据库密码并只保存在
`postgres_credentials` 私有 Docker 卷中；密码不会进入项目 `.env`、镜像、Git 或前端。

本机 Docker 部署（包含同花顺系统级私密凭据的只读挂载）：

```bash
HITHINK_CREDENTIALS_FILE="/Users/你的用户名/Library/Application Support/hithink-finance/credentials.env" \
docker compose -f docker-compose.yml -f docker-compose.hithink.yml up -d --build

docker compose -f docker-compose.yml -f docker-compose.hithink.yml ps
```

部署完成后访问 `http://127.0.0.1:8090`。如需其他端口，可在启动命令前设置 `FRONTEND_PORT`。
`credential-init` 和 `migrate` 成功退出是正常状态；
`postgres`、`backend`、`frontend` 应保持 `healthy`。Futu OpenD 继续运行在 Mac 宿主机，容器通过
`host.docker.internal:11111` 访问。停止服务使用相同的两个 `-f` 参数执行 `docker compose down`；
不要追加 `-v`，否则会删除 PostgreSQL 数据卷。

从原生 macOS PostgreSQL 迁移旧数据到 Docker 时，运行：

```bash
backend/.venv/bin/python backend/deploy/migrate_local_postgres_to_docker.py
```

工具会先在 `.runtime/backups/` 中生成源库和 Docker 库的私有备份，然后以主键去重的方式合并；
已存在的 Docker 记录优先，不会删除旧库。该目录已被 Git 忽略。

需要使用 pgAdmin 查看 Docker 数据库时，运行：

```bash
backend/.venv/bin/python backend/deploy/configure_pgadmin_access.py
```

数据库只会绑定到本机 `127.0.0.1:55433`，脚本会创建一个只读 pgAdmin 账号，并把完整连接参数
保存到本机私有文件 `.runtime/pgadmin.env`。请由用户自行打开该文件并将参数填入 pgAdmin；
密码不会被输出到终端或提交到 Git。

本机 macOS 开发环境已准备两项 `launchd` 用户服务：后端服务和生产构建后的前端预览服务均会在登录后自动启动、异常退出后自动重启。前端固定提供于 `http://127.0.0.1:5173`，并将 `/api` 请求代理到本机后端。前端源码改动后，先执行 `cd frontend && npm run build`，再重启前端服务以加载新页面。

## 已配置服务如何进入 UI

本机后端在真正收到行情、资讯、研究或 AI 对话请求时，才从项目根目录的私有 `.env` 装载
`TUSHARE_TOKEN`、Futu OpenD 地址、LLM 配置和可选的 `DATABASE_URL`。同花顺配置在
[`backend/.env.example`](backend/.env.example) 中保留超时等非敏感参数；其 API Key 由
`hithink-finance` Skill 的系统级私密凭据保存。后端会按 Skill 的安全优先级读取运行时 Key，
但项目 `.env`、前端、Git 提交和日志都不应出现 `HITHINK_FINANCE_API_KEY`。免费腾讯公开行情与
AKShare 公开资讯不需要密钥；这些值绝不返回给前端。
当前 UI 已接通行情、财经资讯、研究分析、个人策略编辑/版本保存，以及首页 AI 研究对话；文档/OCR
和交易日志仍是下一阶段模块。

“自选跟踪”只分析你手动加入的标的：后台默认每 60 分钟按顺序更新至多 30 个自选标的，并将行情、
情绪、基本面、资金流、技术面和个人纪律生成可解释标签，再保存最多 300 字的 AI 研究摘要。点击
自选项会展开当日行情与成交量、同花顺历史 K 线和 Volume Profile。对于 A 股股票，还会读取同花顺
最近披露的利润表、资产负债表、现金流量表、五项估值快照及历史除权除息事件；这些“时间催化剂”只展示
已披露事实，不预测未来事件。基金/ETF 则使用同花顺的基本资料、场内行情/日线、重仓与资产配置、收益
回撤、财务指标和资讯列表，并明确区分定期披露数据与实时数据。系统不会扫描全市场、不会创建委托。生产环境
如运行多个后端副本，只能让一个副本设置 `WATCHLIST_ANALYSIS_SCHEDULER_ENABLED=true`；若不希望
自动调用数据源与 LLM，可设置为 `false` 并在界面手动点击“更新解读”。

### 个股、行业和大盘新闻归因

股票研究不再把全市场快讯直接当成个股情绪。`domain/service/news_relevance.py` 在最近 24 小时
的已采集样本中，按核实的名称、证券代码和行业分类匹配，并仅对命中语句进行词典情绪分析：

- 个股：名称或明确证券代码直接命中；短英文代码必须带 `$`、交易所等明确标记，避免普通词误匹配。
- 行业：命中所属行业但未直接提到目标股票；只作为背景，不冒充个股事实。
- 大盘：央行、主要指数等宏观关键词命中；不是“所有其他股票新闻”的平均值，也不是大盘涨跌预测。

A 股行业与名称通过 Tushare `stock_basic` 获取并缓存，名称可回退同花顺元信息检索。
同花顺契约未提供股票行业字段，因此没有伪造该字段；港美股行业分类或名称缺失时明确降级为代码匹配。
重复标题、超过 24 小时和异常未来时间的新闻排除；两个去重后的个股直接相关标题才使新闻因子可用，
不足不等于利空，也不单独阻止模拟交易。行业与大盘分数不会填补缺失的个股因子。

买入筛选和持仓卖出复核共同使用该新闻因子；用户选定策略不包含新闻因子时，仅展示新闻背景。
纪律、资金预算、价格保护和现有多因子规则优先；新闻不绕过纪律，也不会独立触发真实下单。
每轮候选的分层情绪摘要存入运行记录 `research_notes`，刷新页面后仍可查看。
新闻归因先使用关键词规则，随后对最多 5 条个股直接相关证据调用 LLM 研判；行业与大盘维持独立背景层。
只有至少两条去重的近期个股新闻且模型置信度达到 0.65，模型情绪才进入新闻因子（积极 +0.5、中性 0、消极 -0.5，属于方向编码，不是收益预测）；否则沿用词典分。匹配中的同一句涉及多家公司、否定句、别名和行业同义词
仍可能漏判或误判；基金原有专属资讯研究保留，不宣称已完成基金持仓穿透归因。

### 用量与摘要缓存

公共财经资讯不使用 Tushare 新闻授权：并行合并 AKShare 的东方财富与新浪公开快讯，单源失败保留其他源。
研究时通过 `public_news_search.py` 读取东方财富公开网页检索响应，按名称、明确数字代码、行业最多查询 3 个关键词，每词最多 30 条。
无需登录 Cookie 或额外密钥，不抓取付费正文、不绕过站点限制；结果可能只有公开摘要，不能宣称全网全文覆盖。
检索每请求 3 秒超时、响应最多 1 MB、禁止重定向，缓存 10 分钟，失败仍检查旧条目是否在最近 24 小时内；旧新闻不会包装成今日新闻。
同源尚未结束的采集任务会共享，避免超时后反复创建线程；相同并发查询共享短时缓存。
成功结果缓存 2 分钟，全部上游失败时最多沿用采集后 10 分钟内的缓存，且重新检查新闻仍在请求的时间窗口内。
国内新闻无时区时间按北京时间转成 UTC，支持分开的日期/时间字段；无日期的时间不会猜测为今天。
基金详情的同花顺基金资讯接口独立保留。公共来源并不保证永久可用，超时降级不等于保证抓取成功。

新增新闻研判由 `NEWS_LLM_ENABLED=true` 控制，`NEWS_LLM_MAX_CALLS_PER_HOUR=12` 默认限制每个后端进程每小时最多 12 次新请求，各账户共享额度。
每次最多 5 条、每条 600 字证据，生成预算最多 1800 Token（兼容模型内部推理占用），摘要要求不超过150字，模型请求 20 秒超时。摘要散列忽略时间戳、网址、请求编号和顺序，内容不变复用 24 小时；失败退避 10 分钟。
缓存和额度目前保存在进程内，重启会重置，多进程不会共享；生产多副本需接入集中式缓存/限额。每轮已采用的摘要随模拟运行研究记录持久化。
模型不可用、达到额度或证据不足时沿用关键词分析，不把缺失当成负面。设置页“新闻研判”记录成功、失败与复用；后台定时模拟同样记录用量。
这里没有新增定时器：继续复用自选刷新、研究请求和交易时段每十分钟复核；仅服务正在运行时采集，不保证全天连续归档。

设置页提供今日/本月（UTC）的模型请求、成功/失败、摘要复用、输入/输出及总 Token 统计。
统计从升级后开始，数据库仅记录计数、功能和模型名，不记录提示词、回答正文或密钥。
服务商未报告用量时显示“未报告”，不当成零；缓存输入和推理 Token 为明细，不能再次加到总量。
异常或取消的请求可能已被服务商计费，请以服务商账单为准；这里不估算费用。

自动自选研究检查改由 `WATCHLIST_RESEARCH_INTERVAL_SECONDS` 控制，默认 3600 秒；
旧 `WATCHLIST_ANALYSIS_INTERVAL_SECONDS` 不再生效。模拟交易的 600 秒复核与交易日历不变。
每次获取数据后，只比较行动、个人纪律、策略约束、研究信号、因子和重要新闻：
不比较时间戳、请求 ID、数据源名称、行情的小幅价格波动、错误文案或原始大 JSON。
因子方向/可用性变化直接触发；数值变化需同时达到相对 10% 和绝对 0.01（该因子单位）。
重要新闻采用标题关键词规则（业绩、财报、并购、回购、处罚等），不是完整事件识别模型；
新闻列表滚出旧标题不会触发，新增匹配标题才触发。

比较基准是上次**成功生成摘要**时的数据，并持久化到 PostgreSQL；复用不会移动基准，
因此渐进变化仍能被发现，重启后也能复用。无变化不会仅因过期而重调 LLM。
尾盘自动刷新同样遵守复用；自选“更新解读”按钮可主动重调。复用标签显示原摘要时间（UTC），
实时标签仍来自本轮数据。关键状态变化但模型失败时不继续展示可能误导的旧摘要。
同一自选项在单个后端进程内串行刷新；多副本部署仍须只有一个调度实例。

AI 模拟选股只会对已创建的模拟账户运行：默认在各交易所的实际交易日和常规开市时段，每 10 分钟于
`00/10/20/…` 分钟对齐执行一次，并把每轮结论（包括失败原因）保存到 PostgreSQL。A 股按
北京时间 `09:30–11:30、13:00–15:00`，港股按香港时间 `09:30–12:00、13:00–16:00`，美股按纽约
时间 `09:30–16:00`（自动处理夏令时）。这项规则由根目录私有 `.env` 的
`AI_SIMULATION_*` 配置控制。交易日判断使用独立的 A 股、港股和纽交所日历，会跳过节假日、午休和收市后时段，并处理半日市与美股夏令时。手动执行不受交易时段限制。

总览的「今日最佳三只股票」可切换 A 股、港股、美股，复用模拟买入的因子、策略、个人纪律和预算判断。
在研究样本排名前十名中复核，最多显示三只达标股票；不足时说明原因，不会凑数。已有账户使用真实模拟现金与持仓上限；
无账户时仅按 10 万本金、最多三只预览，不创建账户或交易。行情超过 30 分钟不作为即时入场依据。

AI 模拟持仓使用 `adaptive_v2` 卖出计划：买入时保存风险保护价、首批止盈价和证据；每次有效复核逐仓更新。
无适用个人纪律时，初始止损距离为 2×ATR（成本的 4%–8%），首批止盈为初始风险的两倍；ATR 缺失使用 8%/16%。
首次止盈兑现约一半，剩余仓位采用 2×ATR 移动保护（回撤距离 5%–12%）。保护价只能上移、止盈目标不追涨。
同日资金及机构净流出、且至少两项所选技术因子转弱时收紧保护；跌破 20 日均线并有两项技术风险确认也可退出。
基本面与资讯会读取并记录缺失提示，未验证日期或个股关联的市场新闻不直接触发卖出。个人纪律始终优先；
A 股股票遵守 T+1。过期行情跳过卖出，数据缺失不等于利空。旧仓位在下一次有效复核时补建计划。
这套阈值是项目自定义模拟政策，不是通用盈利标准。十分钟复核不是逐笔止损，跳空时不保证在保护价成交，也不创建真实委托。

候选股研究使用预设的有界高流动性样本池，不扫描整个交易所。腾讯公开行情发生短时网络错误时
会使用有上限的指数退避自动重试；多次失败后，A 股降级到同花顺、再降级到 Futu，港股/美股降级到 Futu。
返回结果保留实际 `source`，不会把备用源伪装成腾讯数据。
